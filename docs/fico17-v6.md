# FICO17 v6

FICO17 v6 is the 17-indicator classroom observation rubric used for coach visits (`/observe`, `/observe2`) and, when
switched on, for the Digital Coach (DC) on self-recordings. The rubric text is data:
`bot/shared/services/coaching/frameworks/fico17-v6/fico17_v6.rubric.json`, generated by
`bot/scripts/build-fico17-v6-rubric.js`. The shared module is `fico17-v6/index.js`.

## Who sets each level

| Indicators | Set by | DC output |
|---|---|---|
| C1 C2 C4 C6 C8 D1 D5 F1 F2 F3 F4 (11) | the DC, from the transcript; a coach may change one with a written reason | a level and evidence |
| C3 C5 C7 D2 D3 D4 (6, "combined") | the coach, from the room, with a written reason (at least 20 characters) | **evidence only** (D2: student turns per half) |

## Design rule: no DC level for the six combined indicators

The six combined indicators never carry a DC level on any surface (reports, debriefs, portal, Flows, PDFs, averages)
for any grade. Their levels depend on what is visible in the room, and transcript-only scoring of them is not yet
reliable enough to show. The DC reports evidence for them, the coach sets the level, and the coach's level, reason
and Rumi's evidence are stored together per visit. These pairs are the calibration set. A DC level for the combined indicators
should only be introduced after it has been checked against them.

The rule is structural. The prompt asks no level for the six. The validator refuses a reply that gives one, and the
scorer drops any that arrives. `tests/coaching/fico17-v6-six-never-dc-graded.test.js` fails if any DC path emits or
renders a level for them.

## Where the coach levels and Rumi's evidence are stored (calibration data)

`/observe` visit scored on v6 (`coaching_sessions`, `framework = 'fico17_v6'`, `observation_type = 'leader_observation'`):

- the coach's level, reason and who set it: `analysis_data -> 'fico17_v6_review' -> 'levels' -> '<code>'`
  (`level`, `because`, `set_by`, `rubric`, `prompt_version`), plus `-> 'd2_counts'` (`children`, `quiet_later`)
- Rumi's evidence: `analysis_data -> 'combined_evidence' -> '<code>'` (`items`: `time`, `quote`, `kind`; `result` is
  only ever `null`, `NA` or `IE`), and `-> 'D2'` (student turns per half)

`/observe2` visit scored on v6 (`observation_field_forms`, `rubric_version = 'fico17_v6'`):

- the coach's level and reason: `evidence_review -> 'v6_levels' -> '<code>'` (`level`, `because`, `set_by`, the rule
  result, `dc_evidence_ids`), plus `evidence_review -> 'd2_counts'`
- Rumi's evidence: `rumi_moments -> 'moments'` (the ids in `dc_evidence_ids` point here)

Example (one row per visit and combined indicator, `/observe`):

```sql
select s.id, c.code,
       s.analysis_data -> 'fico17_v6_review' -> 'levels' -> c.code ->> 'level'   as coach_level,
       s.analysis_data -> 'fico17_v6_review' -> 'levels' -> c.code ->> 'because' as coach_reason,
       s.analysis_data -> 'combined_evidence' -> c.code                         as rumi_evidence
from coaching_sessions s
cross join (values ('C3'),('C5'),('C7'),('D2'),('D3'),('D4')) as c(code)
where s.framework = 'fico17_v6' and s.status = 'observer_review_complete';
```

## The rubric's words: workbook → binding text → JSON

The rubric's words come from the rubric workbook ("FICO17 v6 - what changed", tabs Indicators and Rubric old vs
new). `bot/shared/services/coaching/frameworks/fico17-v6/fico17_v6.source.csv` is that workbook's text, one row per
indicator level. `tests/coaching/fico17-v6-sheet.test.js` lists every difference between it and the JSON. When the
workbook changes: export both tabs to CSV, rewrite `fico17_v6.source.csv` (code, scored_by, name, definition, level,
level_text, example), run the test, carry each difference into `FICO17_v6_rubric.appendix-a.md`, re-run
`bot/scripts/build-fico17-v6-rubric.js`, and run the test again. The workbook has no level names and no Urdu: the
level names come from the binding text, and the Urdu is `fico17_v6.ur.json` (a reviewed draft).

## What the coach chooses from

On every coach path (the `/observe` review Flow, the `/observe2` check, the portal) a level is chosen from four:
the level's name (Not Observed, Developing, Proficient, Highly Effective) with the rubric's level text under it, in
the coach's language (`coachLevelOptions`). There is no N/A and no Couldn't tell for the coach, and D2 has no count
boxes; the Digital Coach keeps its own options (`levelOptions`). Reviews made this way carry the stamp
`fico17-v6-coach-2`. An older review that saved N/A or Couldn't tell keeps that one choice on its list, so it still
shows. The `/observe` review is one indicator per screen (a no-input intro opens each section); the `/observe2`
check's v6 screens are its own Flow (`observe2-evidence-check-v6.json`, `OBSERVE2_CHECK_V6_FLOW_ID`), so the check
every other visit opens is unchanged.

## Switches (all off by default)

- `app_settings.fico_coach_rubric`: coach visits on v6, per region / `ict` / `gb` / `user:<id>`. Only visits to a
  teacher of grades 1-5 (`users.teacher_level` PRIMARY only) reach v6. Grades 6-12 stay on the current rubric.
- `OBSERVE_FICO17_V6_READY`: additionally required for `/observe`.
- `app_settings.fico_dc_rubric`: the DC on self-recordings (`shadow` stores a v6 score beside V3 and never sends it).

A visit keeps the rubric it was stamped with when it started.
