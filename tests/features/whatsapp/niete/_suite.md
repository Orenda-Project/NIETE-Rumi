## Roles & personas (harness, added 2026-08-04)
NIETE is multi-persona (teacher · leader/field-officer · principal), gated on **`users.role`** — source of truth is `LEADER_ROLES = {school_leader, supervisor, coach, principal, aeo}` in `NIETE-Rumi/bot/shared/services/observe/observe-gate.js` (the schema comment "teacher|principal" is stale). Scenarios carry a **`@persona:*`** tag (feature-level default `@persona:teacher`; `observe` = `@persona:coach`; attendance principal scenarios = `@persona:principal`). The suite drives **one throwaway `test_driver`** and **flips its `users.role`** at run start to match the scenario persona — see `whatsapp-targets.yaml → role_switch` (set → read-back → BLOCK on mismatch; staging-preferred since it's a DB write). One-time seed (school + roster) gives the observe visit-picker / principal teacher-list their data; after that only the role flips. `role_switch.enabled:false` until a `test_driver` + creds + seed are provisioned — the blocking action to actually drive observe/attendance.
